01Project overview

This project implements Linux-based malware detection with an automated response pipeline. Newly created or modified files in designated system directories are automatically scanned, suspected malicious binaries are quarantined into an isolated location, and security events are logged. Continuous monitoring is managed via Bash scripting and persistent systemd service automation.

02Problem statement

Files that appear on an endpoint (downloads, uploads, temporary dropped files) may be malicious, and manual on-demand scanning does not keep pace with active threats. Security operations require an automated, persistent endpoint daemon that immediately inspects new or modified files, neutralizes suspected malware through automated quarantine, and generates structured audit trails for incident response.

03Objective

Implement Linux-based malware detection and automated response for newly created or modified files.

  • Automate periodic antivirus signature updates via FreshClam.
  • Leverage the ClamAV daemon (clamd) for low-overhead, resident file scanning.
  • Develop a Bash monitoring engine to detect file modification events in target directories.
  • Implement automated containment that relocates malicious files to an isolated quarantine directory.
  • Run the entire pipeline as a resilient systemd background service with persistent event logging.

06Implementation methodology

  1. Install ClamAV and configure FreshClam to automatically update malware signatures.
  2. Configure and start the ClamAV Daemon (clamd) to provide socket-based scanning.
  3. Develop a custom Bash script that monitors target directories for new and updated files, passing detected paths to the scanner.
  4. Incorporate automated quarantine logic: when an infected file is detected, strip execution permissions and move it immediately to a secure quarantine directory.
  5. Log all scan activities, detection verdicts, and quarantine events to a centralized log file.
  6. Create and enable a systemd service unit to ensure automatic startup and persistent execution across system reboots.

07Detection / testing workflow

  1. Trigger: A file is dropped or edited within a monitored directory.
  2. Scan: The automated monitor invokes ClamAV to verify the file signature against the database.
  3. Contain: Upon signature match, the file is instantly isolated to prevent execution.
  4. Audit: The event details (file path, detection signature name, timestamp, quarantine destination) are appended to the security log.

08Results and validation

The automated endpoint protection pipeline was verified on Linux:

  • Automated Detection: Monitored directories were evaluated with known test files; ClamAV reliably identified threat signatures and reported infection statuses.
  • Automated Containment: Identified test files were moved out of user-accessible paths into the secure quarantine directory with permissions revoked.
  • Reliable Persistence: Verified continuous daemon uptime and automated recovery using systemd service management.

09Challenges and learning

  • Detection Without Response is Incomplete: Detecting malware without immediate automated quarantine leaves an unacceptable window of exposure for endpoint compromise.
  • Signature Freshness: Maintaining an automated update cadence via FreshClam is essential to ensure detection efficacy against newly emerging malware strains.
  • Service Reliability: Running automated Bash monitoring pipelines as native systemd units ensures standard Linux process supervision, automatic restart on failure, and consolidated logging via journalctl.
